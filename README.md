# Подбор запчастей по артикулу

Клиентское приложение на React и Redux (без TypeScript) для web-сервиса «Проценка» (Фаворит Запчасти).
Два шага: ввод артикула → выбор производителя → таблица аналогов и предложений
(название и производитель, цена, остаток; склады раскрываются по клику).

- Светлая и тёмная тема (по умолчанию тёмная, выбор пользователя запоминается).
- Состояния загрузки (скелетоны и спиннер), понятные ошибки: сеть, таймаут, ошибки сервиса и ключа, пустой результат.
- Документация API: https://lk.favorit-parts.ru/static/wsprice.pdf

## Стек

Vite 7, React 19, Redux Toolkit 2 + react-redux 9, Bootstrap 5.3 (только CSS), шрифты IBM Plex (через `@fontsource`),
Vitest (тесты логики и стора), ESLint 9, Prettier 3. Docker + nginx для выкладки на сервер.

## Требования

- Node.js 20.19 или новее (этого требует Vite 7; у вас v24.21.0 — подходит). Проверка: `node -v`.
- npm (идёт вместе с Node.js).
- Git — для шага с GitHub.
- Docker — только для выкладки на сервер (на своём компьютере не обязателен).

## 1. Запуск на своём компьютере (Windows 10)

1. Распакуйте архив `favorit-parts.zip`, например в `C:\projects\favorit-parts`.
2. Откройте PowerShell (или «Терминал») и перейдите в папку проекта:

   ```powershell
   cd C:\projects\favorit-parts
   ```

3. Установите зависимости. Команда создаст папку `node_modules` и файл `package-lock.json`:

   ```powershell
   npm install
   ```

4. Запустите сервер разработки:

   ```powershell
   npm run dev
   ```

5. Откройте в браузере адрес, который покажет Vite (обычно http://localhost:5173).
   Для проверки введите `01089` → выберите, например, `GLASER`.
   Остановить сервер: `Ctrl + C` в терминале.

### Проверка качества кода

Одна команда запускает линтер, тесты и production-сборку:

```powershell
npm run check
```

Отдельно: `npm run lint`, `npm test`, `npm run build`, `npm run format:check` (проверка форматирования),
`npm run format` (автоформатирование). Локальный просмотр production-сборки: `npm run build`, затем `npm run preview`
(http://localhost:4173, прокси к API работает и там).

### Настройки и ключ API (`.env`)

| Файл           | В git? | Назначение                                                                           |
| -------------- | ------ | ------------------------------------------------------------------------------------ |
| `.env.example` | да     | Шаблон без ключа: показывает, какие переменные нужны                                 |
| `.env`         | нет    | Ваши локальные значения. В архиве он уже создан и содержит демо-ключ из документации |
| `.env.local`   | нет    | Необязательно: перекрывает `.env` (удобно, чтобы временно подставить другой ключ)    |

`.env` и `.env.local` перечислены в `.gitignore`, поэтому в GitHub ключ не попадёт.
Если вы получили проект из GitHub (в нём есть только `.env.example`), создайте `.env` сами:

```powershell
Copy-Item .env.example .env
```

и впишите ключ в строку `VITE_FAVORIT_API_KEY=`. После изменения `.env` перезапустите `npm run dev`.

> Важно: переменные `VITE_*` вшиваются в клиентский бандл, поэтому на опубликованном сайте ключ виден любому
> посетителю в браузере (вкладка Network или исходный код). Из репозитория он скрыт, но не от посетителей сайта.
> Для демо-ключа этого достаточно (он и так опубликован в документации сервиса). Для боевого ключа нужна серверная часть:
> например, nginx подставляет ключ в запрос к API, а в браузере ключа нет, — это за рамками тестового задания.

## 2. Как устроена работа с API

Браузер всегда обращается на **свой же домен** по пути `/api/...`, а не на `api.favorit-parts.ru` напрямую:

| Где запущено                     | Кто проксирует `/api` → `https://api.favorit-parts.ru` |
| -------------------------------- | ------------------------------------------------------ |
| `npm run dev`, `npm run preview` | Vite (настройка в `vite.config.js`)                    |
| Docker (сервер)                  | nginx (файл `nginx.conf`)                              |

Зачем: нет проблем с CORS и с блокировкой «смешанного контента», когда сайт открыт по HTTPS, а API по HTTP.

Запросы:

1. Шаг 1: `GET /hs/hsprice/?key=…&number=<артикул>` — список производителей.
2. Шаг 2: `GET /hs/hsprice/?key=…&number=<артикул>&brand=<производитель>&analogues=on` — искомая позиция и аналоги.

Как отображаются данные:

- Цена в списке — минимальная цена среди складов, где есть остаток (если цены на складах различаются — «от …»).
  Устаревшее поле `price` из ответа не используется, цены берутся из складов.
- Валюта в документации не указана, поэтому принято «₽».
- Время отгрузки показывается по Москве: «заказ до HH:mm МСК».
- Порядок позиций в ответе API нестабилен, поэтому сортировка делается на клиенте:
  сначала позиции в наличии (по возрастанию цены), затем остальные.
- Устаревшие ответы отбрасываются: если пользователь быстро сменил запрос, результат старого запроса не затрёт новый.

## 4. Выкладка на облачный сервер

Приложение собирается в статические файлы; их раздаёт nginx, он же проксирует `/api`.
Всё это упаковано в `Dockerfile`, поэтому на сервере достаточно Docker.

### Вариант А. Виртуальный сервер (VPS) с Docker — подходит для Timeweb Cloud и любого другого провайдера

1. Создайте сервер с Ubuntu 22.04/24.04 в панели провайдера и подключитесь по SSH:

   ```bash
   ssh root@IP_СЕРВЕРА
   ```

2. Установите Docker (официальный скрипт установки):

   ```bash
   curl -fsSL https://get.docker.com | sh
   ```

3. Скачайте проект из GitHub (для приватного репозитория понадобится токен доступа), создайте `.env` из шаблона,
   впишите в него ключ и соберите образ (ключа в репозитории нет, поэтому без этого сборка остановится с сообщением
   «не задан VITE_FAVORIT_API_KEY»):

   ```bash
   git clone https://github.com/ВАШ_ЛОГИН/favorit-parts.git
   cd favorit-parts
   cp .env.example .env
   nano .env            # впишите VITE_FAVORIT_API_KEY=..., сохраните: Ctrl+O, Enter, выход: Ctrl+X
   docker build -t favorit-parts .
   ```

   Вместо файла `.env` ключ можно передать аргументом сборки:
   `docker build --build-arg VITE_FAVORIT_API_KEY=ваш-ключ -t favorit-parts .`

4. Запустите контейнер на 80 порту (перезапускается сам после перезагрузки сервера):

   ```bash
   docker run -d --name favorit-parts --restart unless-stopped -p 80:80 favorit-parts
   ```

5. Откройте `http://IP_СЕРВЕРА` в браузере. Если не открывается — проверьте, что в панели провайдера и в
   файрволе (`ufw status`) разрешён входящий порт 80.

Обновление после изменений в коде: `git pull`, затем
`docker build -t favorit-parts .`, `docker rm -f favorit-parts` и снова `docker run …` из пункта 4.

### Вариант Б. Приложение из GitHub-репозитория в панели облака

Некоторые облака (в том числе Timeweb Cloud) умеют собирать приложение прямо из GitHub-репозитория, в том числе по
`Dockerfile`. Порядок: подключить GitHub-аккаунт, выбрать репозиторий и ветку `main`, указать тип «Docker» (сборка по
`Dockerfile` из корня репозитория), порт контейнера — 80. Ключ нужно передать как переменную (аргумент) сборки
`VITE_FAVORIT_API_KEY` в настройках приложения: в репозитории его нет, и без него сборка остановится. Точные названия пунктов меню у провайдера могут отличаться —
ориентируйтесь на его актуальную документацию. Вариант А не зависит от интерфейса панели и проще для диагностики.

### Домен и HTTPS

1. Создайте у регистратора A-запись домена на IP сервера.
2. Для HTTPS проще всего поставить перед контейнером обратный прокси с автоматическими сертификатами
   (например, Caddy или nginx + Certbot) либо воспользоваться сертификатом в панели провайдера.
   Приложению это не мешает: оно ходит на `/api` своего же домена и работает и по HTTP, и по HTTPS.

### Статические хостинги без прокси (GitHub Pages и т. п.)

GitHub Pages не умеет проксировать запросы, поэтому с настройками по умолчанию API там работать не будет.
Если нужен именно такой хостинг, задайте при сборке `VITE_API_BASE_URL=https://api.favorit-parts.ru`
(сервис при этом должен разрешать запросы с вашего домена — CORS; это не проверялось) либо используйте
хостинг с правилами перенаправления (rewrites) на `https://api.favorit-parts.ru`.

## 5. Возможные проблемы

| Симптом                                               | Что делать                                                                                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm` не запускается в PowerShell (политика скриптов) | Запустите команды в `cmd`, либо один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`                                                      |
| `Unsupported engine` / ошибки при сборке              | Проверьте `node -v`: нужна версия 20.19+                                                                                                                      |
| Порт 5173 занят                                       | Vite сам предложит другой порт, либо `npm run dev -- --port 3000`                                                                                             |
| «Нет связи с сервисом»                                | Нет интернета или недоступен `api.favorit-parts.ru`. Проверьте, что dev-сервер запущен именно через `npm run dev` (прокси `/api`)                             |
| «Неверный ключ» / «Не указан ключ»                    | Проверьте `.env` / `.env.local` (есть ли в `.env` значение `VITE_FAVORIT_API_KEY`). После правки перезапустите `npm run dev`; для Docker — пересоберите образ |
| На сервере сайт открывается, а поиск даёт ошибку      | Проверьте, что сервер выходит в интернет и резолвит `api.favorit-parts.ru`: `docker logs favorit-parts`, `curl -I https://api.favorit-parts.ru`                |
| `npm ci` падает в Docker-сборке                       | В репозитории нет синхронного `package-lock.json`: выполните `npm install` локально и закоммитьте обновлённый файл                                            |
